### How an autogrow input becomes a bindable socket name

The socket names are generated by `Autogrow.TemplatePrefix.__init__` in
`comfy_api/latest/_io.py`:

```python
self.names = [f"{self.prefix}{i}" for i in range(self.max)]
```

`range(self.max)` is **zero-based**, so the image slots at this revision are
`ref_image_0` through `ref_image_8`. The published graph declares the first
four — `ref_image_0`, `ref_image_1`, `ref_image_2`, `ref_image_3` — matching the
request contract's maximum of four references
(`ReferenceToVideoRequest.references`, `max_length=4`).

Note that the *prompt* ordinals are a separate, one-based numbering: the node
docstring presents references to the tokenizer as `<Picture i>` / `<Video k>` /
`<Audio j>` with 1-based ordinals per type. Socket index and prompt ordinal are
not the same number.

## `LoadImage` — declared inputs

Read from `nodes.py` at the same revision.

| Input name | Type | Required | Notes as declared |
| --- | --- | --- | --- |
| `image` | filename combo (`image_upload: True`) | yes | resolved through `folder_paths.get_annotated_filepath` |

Outputs are `IMAGE` (slot 0) and `MASK` (slot 1).

`image` is a plain string widget, which is why it — and not the conditioning
node's `ref_image_N` socket — is the input the binder writes. `ref_image_N` is
an `IMAGE` socket and in API format carries a `[node_id, slot]` link, whereas
`input_0`..`input_3` carry the staged input's workspace-relative path string.

## Why this graph differs from `minimax-h3-t2v`

`minimax-h3-t2v/workflow-api.json` drives `MiniMaxH3ImageToVideo`, whose only
image inputs are `first_frame` and `last_frame`, both optional, and neither is
declared in that graph. The binder mutates only declared node inputs and raises
`WorkflowBindingError("binding_input_missing")` when an `input_name` is absent,
so no reference can be bound into the published text-to-video graph. This graph
declares four `LoadImage` nodes (`201`–`204`) feeding, in order, `ref_image_0`,
`ref_image_1`, `ref_image_2` and `ref_image_3` on node `105`, so the four
allowlisted sources `input_0`..`input_3` have somewhere to land.
